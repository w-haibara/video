# 121: クロストラック移動のバグ修正 — クリップ重なり防止と空トラック保持

**背景:** タスク 117 で実装されたクリップのトラック間ドラッグ移動に 2 つのバグがある。(1) 移動先トラックでクリップが重なる場合がある。(2) あるトラックからクリップをすべて移動すると、そのトラックが自動的に削除されてしまう。いずれも `sequence-ops.ts` の `moveClip` 関数内のクロストラック移動パスに起因する。

**問題の原因分析:**

1. **クリップ重なりバグ**: `findNonOverlappingPosition` のフォールバック処理に問題がある。スナップ後も重なりが解消できない場合、`clips.find((c) => c.id === movingClipId)` で元位置を取得するが、クロストラック移動では移動中のクリップが移動先トラックに存在しないため `undefined` になり、`newStartMs`（重なりのある位置）をそのまま返してしまう。加えて、スナップループ内で `endMs` が初回計算値のまま更新されず、2 つ目以降のクリップとの重なり判定が不正確になる。
2. **空トラック自動削除バグ**: `moveClip` のクロストラック移動パス末尾で `.filter((track: Track) => track.clips.length > 0)` を適用しており、クリップが 0 になったソーストラックを暗黙的に削除してしまう。タスク 119 で明示的なトラック削除（右クリックメニュー + 確認ダイアログ）を実装済みであり、暗黙的な削除は不要。

**対象ファイル:**
- `app/frontend/src/lib/sequence-ops.ts`（`findNonOverlappingPosition` 修正・`moveClip` 修正）

**変更内容:**

**A. `findNonOverlappingPosition` のクロストラック移動対応修正**

- [x] スナップループ内で `pos` を更新した際に、重なり判定に使う終了位置も `pos + durationMs` で再計算するよう修正する
- [x] フォールバック処理を修正する: スナップ後も重なりが解消できない場合、ソートされた `others` の隙間を走査して、`durationMs` 分の空きがある位置を探す。隙間が見つかればその位置を返す。見つからない場合は最後のクリップの終了位置を返す
- [x] フォールバックで `newStartMs` をそのまま返すパスを削除し、常に重なりのない位置を返すことを保証する

**B. `moveClip` のクロストラック移動パスから空トラック自動削除を除去**

- [x] `.filter((track: Track) => track.clips.length > 0)` の行を削除し、クリップが 0 になったソーストラックを保持するよう変更する

**確認方法:** 既存の `bun run test` が通ること。次のタスク 122 で追加するテストが通ること。手動確認: クリップを別トラックにドラッグ移動した際に、移動先でクリップが重ならないこと。ソーストラックのクリップがすべて移動された後もトラックが残っていること。
