Canvas / FFmpeg パリティ不一致分析レポート

Canvas Export パリティテストで検出された 6 つの不一致ケースについて、原因と発生メカニズムを解説する。

テスト素材: ビデオ＝赤一色 (253,0,0)、画像＝青一色 (0,0,254)

1
overlay-blend YUV 色空間

2トラック構成。Track 1＝赤ビデオ、Track 2＝青画像を overlay ブレンドで合成。

Frame 1

FFmpeg
Canvas
FFmpeg: #D1005F (209, 0, 95)
Canvas: #FD0000 (253, 0, 0)

発生原理: YUV 色空間での blend 演算

FFmpeg の blend=all_mode=overlay フィルタは入力ストリームを YUV420p ピクセルフォーマットのまま処理する。テストビデオの赤 (253,0,0) は YUV エンコード時に:

RGB(253, 0, 0) → YUV(81.5, 90.3, 240.0) (BT.601) RGB(0, 0, 254) → YUV(28.8, 218.3, 18.4)

overlay blend 計算は各 YUV チャネルに対して行われ、結果を RGB に逆変換する。このとき Y（輝度）に対する overlay と UV（色差）に対する overlay は、RGB 空間での overlay とは異なる結果を生む。

一方 Canvas の globalCompositeOperation = "overlay" は RGB 空間で直接計算するため、正しい overlay 結果を得る。FFmpeg 側の色ずれは YUV 空間での演算に起因する構造的差異。

Frame 1

FFmpeg: #1E1447 (30, 20, 71)
Canvas: #FE00FE (254, 0, 254)

発生原理: YUV difference が RGB difference と根本的に異なる

RGB 空間での difference は直感的:

difference(R) = |253 - 0| = 253 difference(G) = |0 - 0| = 0 difference(B) = |0 - 254| = 254 結果: (253, 0, 254) = マゼンタ ← Canvas の結果

しかし FFmpeg は YUV 空間で difference を計算する:

difference(Y) = |81.5 - 28.8| = 52.7 difference(Cb) = |90.3 - 218.3| = 128.0 → 中立点 difference(Cr) = |240.0 - 18.4| = 221.6 → clamp → 221.6 YUV(52.7, 128.0, 221.6) → RGB 逆変換 → 暗い紫紺

YUV の差分を取ると 輝度差が小さいため結果は暗くなる。赤と青は RGB では最大距離だが、YUV では輝度 (Y) がどちらも低く近い値。これが YUV 色空間での blend 演算が RGB と大きく乖離する最も顕著な例。

発生原理: トランジション中の背景合成の差

Frame 11 (t=1000ms) ではトランジション進行中で、outgoing クリップ (赤) が fade out している。

  • FFmpeg: fade out する赤クリップが残像として低 opacity で描画され、暗い赤が青の transform されたクリップの背景に残る → #090DE5
  • Canvas: outgoing クリップの opacity が 0 に到達しているため、transform された青クリップのみが黒背景上に描画される → #0000FE

fade のタイミング曲線と opacity 計算の差により、特定フレームで outgoing クリップの残り方が異なる。Frame 11 のみ 39% diff で、他のフレームは一致。

発生原理: multiply blend + fade のタイミング差

multiply blend: result = base × blend / 255。赤 (253,0,0) × 青 (0,0,254) はどのチャネルでも一方が 0 なので結果は黒 (0,0,0)。

Canvas の #000000 は数学的に正しい。FFmpeg の #001600 (G=22) は、テストビデオの MP4 デコード時の YUV→RGB 変換で G チャネルに 22 程度のアーティファクトが発生し、それが multiply 計算後も残っているため。

Frame 8, 9 が 100% diff なのは、トランジション中の opacity 計算タイミングの差で、CanvasCompositor が一方のクリップしか描画しないフレームがある一方、FFmpeg は常に両クリップを合成しているため。

発生原理: screen blend の色空間差 + YUV デコード G 漏れ

screen blend: result = 1 - (1-base)(1-blend)。赤+青の screen 結果:

screen(R) = 1 - (1-253/255)(1-0/255) = 253/255 → 253 screen(G) = 1 - (1-0)(1-0) = 0 screen(B) = 1 - (1-0/255)(1-254/255) = 254/255 → 254 Canvas 結果: (253, 0, 254) = #FE00FE ✓ 正しい

FFmpeg の G=19 は、テストビデオ MP4 の YUV→RGB 変換で G チャネルに発生するアーティファクト。純赤 (255,0,0) は YUV420p でクロマサブサンプリングされると、デコード時に G 成分が完全に 0 に戻らない。

41.67% diff は crop 外領域の G 漏れ (23 > channelTolerance 40 の閾値以内だが) と crop 境界のアンチエイリアス差に起因。

発生原理: blur アルゴリズムの差とエッジ処理

Canvas は CSS filter: blur(Npx) (Gaussian blur) を使用し、FFmpeg は boxblur を使用。

  • カーネル形状: CSS blur は Gaussian（ベル曲線型の重み付け）、FFmpeg boxblur は矩形（均等な重み付け）。同じ強度でもぼかしの広がり方が異なる
  • エッジ処理: transform で回転+縮小されたクリップの境界で、blur の端の処理が異なり、背景（黒）との境界のにじみ幅が異なる
  • G チャネル漏れ: 赤領域内部でも FFmpeg は G=23 を出力（YUV デコード由来）

20.51% diff は主にクリップ境界のぼかし幅の差によるもの。

まとめ: 原因の分類

ケース diff 原因分類 根本原因
overlay-blend 100% YUV 色空間 FFmpeg の blend フィルタが YUV 空間で演算するため、RGB 空間での overlay と結果が大きく乖離
difference 100% YUV 色空間 YUV の difference は輝度差が小さくなり暗い色に。RGB difference はチャネルごとの絶対差でマゼンタに
transition-with-transform 39% (1f) Compositor fade out する outgoing クリップの opacity タイミング差。特定フレームで背景が赤 vs 黒に分岐
blend-mode-transition 100% (2f) Compositor トランジション中の blend mode + opacity 合成順序の差。Canvas 側で片方のクリップだけが描画されるフレームがある
crop-blend 41.67% YUV 色空間 screen blend の G チャネル漏れ（YUV デコード由来）+ crop 境界のアンチエイリアス差
video-filter-transform 20.51% アルゴリズム差 CSS Gaussian blur vs FFmpeg boxblur のカーネル形状差 + transform 後の境界にじみ差

共通のアーティファクト: YUV デコード G チャネル漏れ

6 ケース全てに共通して、FFmpeg 側で G チャネルに 19〜23 の値が出現する。これはテストビデオの赤 (255,0,0) が YUV420p エンコード→デコードを経る際に発生する量子化誤差。純赤は YUV420p のクロマサブサンプリング (4:2:0) で色差信号が 2×2 ブロック単位に平均化されるため、デコード時に G/B チャネルが正確に 0 に復元されない。
